# Товарный отчет (Telegram)

Витрина «план / факт / остаток» по сети магазинов и Telegram-бот, который отдает отчет по запросу.

## Как это работает

- `app.py` - раз в 24 часа (и сразу при старте) собирает витрину по месяцам, магазинам, бит литерам и категориям. Данные (план, продажи по товарам, остатки) читает с Drive. Дата обновления = последняя дата в Sales_sku_target: в папке `REPORTS_FOLDER_ID` создается папка с этой датой (`ДД.ММ.ГГГГ`), туда кладутся `report.xlsx` (все филиалы) и `{филиал}.xlsx`. После загрузки всех файлов дата пишется в `pipeline_state.csv` (строка `tovarnyi_otchet_tgbot`, `updated_at` в ISO). Пересчет за прошлую дату (`--as-of`) дату в pipeline_state не откатывает.
- `bot.py` - Telegram-бот (long polling). Команды:
  - `/updated` - дата из `pipeline_state.csv` (строка `tovarnyi_otchet_tgbot`);
  - `/report` - по дате из `pipeline_state.csv` находит папку отчета и присылает файлы доступных филиалов или `report.xlsx` при доступе `all` (см. «Доступ»);
  - `/my_store` - список доступных филиалов.
- `drive_client.py` - работа с Google Drive API (скачивание/загрузка файлов, экспорт Google Таблицы в CSV).

## Доступ

Права задает Google Таблица **Users** (id в `USERS_SHEET_ID`), одна строка - одна пара «пользователь - филиал»:

- `user_id` - числовой id пользователя в Telegram (узнать можно, например, у `@userinfobot`); `access` - название филиала так, как оно записано в поле «магазин» отчета, или `all`.
- Таблица читается при каждой команде, поэтому изменения прав действуют сразу, без перезапуска бота.
- Пользователь, которого нет в таблице, получает «Нет доступа» и свой `user_id` (чтобы его можно было добавить). Исключение: `/updated` отвечает всем.

`as_of` - дата обновления данных (из `pipeline_state.csv`, ДД.ММ.ГГГГ). Если у филиала нет строк в отчете (например, для Алматы Esentai Mall нет плана), файл филиала не формируется, бот сообщает об этом отдельным сообщением.


## Листы отчета

`План факт по филиалам`: 
- столбцы - филиалы (в файле филиала - только его столбец); 
- строки - план год, план месяц (дневной план), факт YTD, факт MTD, выполнение плана год / месяц, факт YTD LY, факт MTD LY, откл факт YTD YoY, откл факт MTD YoY (к тем же датам прошлого года).

`План факт по категориям`: 
- столбцы - месяц, магазин, бит литера, категория, доли, план категории, факт MTD, выполнение плана, плана осталось выполнить, остаток шт, средняя цена продажи с учетом скидки, сколько шт продать осталось, возможность выполнить план (по остатку), даты факта и остатка.

`Артикулы` (во всех файлах одинаковый, чтобы филиал видел, где есть товар, и просил перемещение): 
- строка = магазин + артикул + бит литера + поставщик + категория + подкатегория + цвет + размер (цвет и размер могут быть пустыми); 
- коллекция, вставка, продажи шт за 12 мес, месяцев с остатком (за те же 12 месяцев - число месяцев с остатком > 0 на конец месяца, по срезам 01.ММ.ГГГГ), скорость продаж базовая (продажи шт за 12 месяцев до даты отчета / 12, без учета дней без остатка), скорость продаж с учетом наличия (продажи шт за 12 мес / месяцев с остатком, пусто при 0), текущий остаток;
- порядок: магазин, артикул, продажи шт за 12 мес по убыванию.

`Обозначения`: 
- расшифровка YTD, MTD, LY, YoY, скорость продаж базовая.


## Запуск

Нужны `.env` (токен бота, id файлов на Drive, `PIPELINE_STATE_ID`, папка отчетов `REPORTS_FOLDER_ID`, id таблицы доступов `USERS_SHEET_ID`) и папка `creds/` с OAuth-файлами Google (в репозитории их нет).

```
docker compose up -d --build   # сервисы app и bot
```

Без Docker: `pip install -r requirements.txt`, затем `python app.py --schedule` и `python bot.py`.
