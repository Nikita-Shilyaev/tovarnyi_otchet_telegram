# Товарный отчет (Telegram)

Витрина «план / факт / остаток» по сети магазинов и Telegram-бот, который отдает отчет по запросу.

## Как это работает

- `app.py` - раз в 24 часа (и сразу при старте) собирает витрину по месяцам, магазинам, бит литерам и категориям и перезаписывает `report.xlsx` на Google Drive. Данные (план, продажи по товарам, остатки) читает с Drive.
- `bot.py` - Telegram-бот (long polling). Команды:
  - `/updated` - дата, по которую обновлены данные;
  - `/report` - присылает отчет по доступным филиалам (см. «Доступ»);
  - `/my_filial` - список доступных филиалов.
- `drive_client.py` - работа с Google Drive API (скачивание/загрузка файлов, экспорт Google Таблицы в CSV).

## Доступ

Права задает Google Таблица **Users** (id в `USERS_SHEET_ID`), одна строка - одна пара «пользователь - филиал»:

- `user_id` - числовой id пользователя в Telegram (узнать можно, например, у `@userinfobot`); `access` - название филиала так, как оно записано в поле «магазин» отчета, или `all`.
- Таблица читается при каждой команде, поэтому изменения прав действуют сразу, без перезапуска бота.
- Пользователь, которого нет в таблице, получает «Нет доступа» и свой `user_id` (чтобы его можно было добавить). Исключение: `/updated` отвечает всем.

`as_of` - дата обновления данных (название листа `report.xlsx`, ДД.ММ.ГГГГ). Если у филиала нет строк в отчете (например, для Алматы Esentai Mall нет плана), файл не формируется, бот сообщает об этом отдельным сообщением.

## Поля отчета

месяц, магазин, бит литера, категория, план, факт MTD, выполнение плана, плана осталось, остаток шт, средняя цена продажи с учетом скидки, сколько шт продать осталось, возможность выполнить план (по остатку), даты факта и остатка.


## Запуск

Нужны `.env` (токен бота, id файлов на Drive, id таблицы доступов `USERS_SHEET_ID`) и папка `creds/` с OAuth-файлами Google (в репозитории их нет).

```
docker compose up -d --build   # сервисы app и bot
```

Без Docker: `pip install -r requirements.txt`, затем `python app.py --schedule` и `python bot.py`.
